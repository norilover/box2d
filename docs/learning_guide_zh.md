# Box2D 源码学习指南

本文面向希望从使用 API 进一步理解 Box2D 内部实现的读者。指南对应当前仓库中的 Box2D 3.2.0；源码结构和接口可能与旧版 Box2D 2.x 有明显差异。

本次模块说明以本地提交 `956ce4e` 为代码基线，整理日期为 2026-10-24。版本号来自根目录 CMake，并不表示任意同版本教程都与此提交一致。这里的“初学者”指初次学习物理引擎；如果还不能读 C 的指针、结构体和基本编译错误，先补这些基础，再进入源码。

## 怎么学

不要试图从第一个 `.c` 文件开始顺序读完整个仓库。更有效的方式是从一个具体问题出发，例如“一个动态盒子落到地面上时，Box2D 怎样发现碰撞并阻止它继续下落？”，然后沿着相关数据和函数逐步追踪。

每次阅读时记录四件事：

1. 输入是什么，来自用户 API、上一阶段还是缓存数据？
2. 关键数据存在哪里，结构体之间怎样通过 id 或索引关联？
3. 哪个函数会创建、更新或释放这些数据？
4. 如何从测试、事件或样例中观察到结果？

先建立宏观调用关系，再深入单个算法。SIMD、多线程、内存池等优化适合在基础路径清晰之后研究。

## 项目地图

| 目录 | 用途 | 学习时的入口 |
| --- | --- | --- |
| `include/box2d` | 对外公开的 C API 和类型 | `box2d.h`、`collision.h`、`types.h` |
| `src` | 物理引擎内部实现 | `physics_world.c`、`body.c`、`shape.c`、`solver.c` |
| `test` | 单元测试，也直接包含部分内部头文件 | `test_world.c`、`test_collision.c`、`test_determinism.c` |
| `samples` | 可视化场景和交互示例，主要使用 C++ | `sample_stacking.cpp`、`sample_collision.cpp` |
| `docs` | API 概念、物理模拟和碰撞算法说明 | `overview.md`、`simulation.md`、`collision.md` |
| `shared` | 样例、测试和基准共享的辅助代码 | `benchmarks.c`、`determinism.c`、`human.c`、`utils.c` |
| `benchmark` | 独立基准程序及已有测量结果 | `main.c`；实验使用 Release 构建 |
| `extern`、`scripts`、`.github` | 第三方辅助代码、维护脚本与 CI | 需要研究工程集成时阅读 |

Box2D 的核心库用 C17 编写；samples 使用 C++20。样例中的 C++ 是测试床和渲染应用，不代表物理引擎核心是 C++。

## 第一阶段：理解 API 和基本对象

先读项目[概览](overview.md)、[基础模块](foundation.md)和[模拟手册](simulation.md)的开头，再浏览公开头文件 `include/box2d/box2d.h`。重点掌握这些对象的关系：

- World 管理一组刚体、形状、关节和接触。
- Body 表示刚体的运动状态；Shape 提供碰撞几何和材料属性。
- Contact 由引擎根据形状重叠自动维护。
- Joint 是用户创建的约束，例如转动关节、距离关节和轮关节。
- `b2WorldId`、`b2BodyId` 等 id 是不透明句柄，应用保存和传递句柄，而不是内部对象指针。

从 [`test_world.c`](../test/test_world.c) 中的 `HelloWorld` 开始读。它展示了完整的基本流程：初始化默认定义、创建 world 和 body、创建 shape、按固定时间步调用 `b2World_Step`、读取刚体位置，最后销毁 world。

读完后，试着不看源码，用自己的话解释：Body 和 Shape 为什么分开？静态、运动学和动态刚体有什么区别？为什么创建定义要先调用 `b2Default...Def()`？

## 第二阶段：从样例理解引擎的使用方式

构建并运行 samples，在界面里观察不同场景。初读可选 `sample_stacking.cpp`，它展示了刚体堆叠、接触稳定性和交互；之后再选关节、连续碰撞、传感器或事件相关样例。样例文件通常包含场景构造代码，基类和每帧更新入口可从 `samples/sample.h` 继续追。

构建命令见仓库 [`README.md`](../README.md)。CMake presets 包含 Windows、Linux 和 macOS 的构建配置；也可以关闭 samples，只构建库和测试，以减少初期需要理解的代码量。

可直接复制的 Windows / Linux 命令以及完整 C 示例见[第 01 篇](learning/01_start.md)。测试通过 `test` 可执行文件运行；当前没有 CTest 测试注册，筛选参数是 `WorldTest` 这样的测试组全名。

## 第三阶段：追踪一帧模拟

在 `src/physics_world.c` 的 `b2World_Step` 处设置断点。这是最好的主线入口之一。它的高层流程可以概括为：

```text
b2World_Step
  ├─ b2UpdateBroadPhasePairs   更新候选形状对并创建接触
  ├─ b2Collide                 更新接触点和接触状态
  ├─ b2Solve                   积分并求解接触与关节约束
  ├─ b2OverlapSensors          更新传感器重叠
  └─ 发布本步事件、清理任务状态
```

建议依次阅读：

1. `src/physics_world.c`：world 生命周期、step 入口、接触更新的组织方式。
2. `src/broad_phase.c` 和 `src/dynamic_tree.c`：怎样快速找出可能碰撞的形状对。
3. `src/contact.c`、`src/manifold.c`：接触如何创建、更新，以及接触点如何表示。
4. `src/solver.c` 和 `src/contact_solver.c`：求解阶段怎样安排，约束冲量怎样改变速度和位置。
5. `src/constraint_graph.c`、`src/island.c`、`src/solver_set.c`：哪些约束能并行处理，休眠和唤醒的数据怎样组织。

每追进一层都回答一个问题：这一层拿到什么数据、产生什么结果、下一层由谁调用？对 `b2World_Step` 做完这张调用图后，再跟踪一对实际发生碰撞的 shape，会更容易理解系统。

## 第四阶段：拆开碰撞算法

阅读[碰撞手册](collision.md)，先熟悉圆、胶囊体、凸多边形、线段、凸包、AABB 和动态树等概念。再从几何查询入手：点包含、射线投射、形状投射、形状距离和时间碰撞。

推荐顺序是 `geometry.c`、`hull.c`、`distance.c`、`manifold.c`，然后回到 `broad_phase.c` 和 `contact.c` 看它们怎样被刚体模拟复用。这样可以区分“几何上是否相交”“哪些对象值得检查”和“如何生成供求解器使用的接触约束”。

配合 `test/test_collision.c`、`test/test_distance.c` 和 `test/test_dynamic_tree.c` 阅读。测试通常能帮助确认边界条件、几何约定和容差的实际含义。

## 第五阶段：理解约束求解

先复习刚体的线速度、角速度、质量、转动惯量和冲量，再阅读 `src/solver.c`。关注一个时间步如何拆成子步、约束如何准备、冲量如何迭代，以及位置如何更新。随后查看 `src/contact_solver.c` 和关节实现，例如 `src/revolute_joint.c`、`src/distance_joint.c`。

再研究 `src/constraint_graph.c` 和 solver stages：碰撞图的组织关系如何影响可并行执行的工作？休眠的 body 或 island 怎样从活动集合中移出，再在受力或碰撞时唤醒？读到这里再看 SIMD 和 worker 调度会更有上下文。

## 第六阶段：用测试和实验巩固

测试是理解实现的重要材料，因为许多测试检查的不只是 API 返回值，还包括内部集合、接触状态、确定性和非法输入处理。按主题选择测试：

- World、刚体和接触：`test/test_world.c`
- 几何与碰撞：`test/test_collision.c`、`test/test_shape.c`
- 动态树：`test/test_dynamic_tree.c`
- 多线程：`test/test_thread.c`
- 确定性：`test/test_determinism.c`
- 输入验证：`test/test_invalid_input.c`

每次只改变一个因素，例如时间步、子步数量、摩擦、恢复系数或 worker 数量。先写下对运动结果或性能的预测，再运行样例或对应测试。若结果与预期不同，沿 API 输入和 `b2World_Step` 调用链追踪原因。

## 六周实践安排

可以按每周 6～8 小时安排；数学或 C 基础薄弱时，将一周拆成两周。时间只作参考，以产出和理解为准。

| 周次 | 阅读与练习 | 留下的产物 | 完成标准 |
| --- | --- | --- | --- |
| 第 1 周 | 第 01、02 篇；运行 `WorldTest` 和最小程序 | 环境命令、位置日志、对象关系图 | 解释 Body/Shape 分工和最终落点 |
| 第 2 周 | 第 03、08 篇；断点跟踪与事件实验 | 一帧调用图、接触/传感器日志 | 区分候选、接触、事件与查询 |
| 第 3 周 | 第 04、05 篇；距离、动态树与薄墙实验 | 三个几何实验与预测/实际结果 | 区分宽相、窄相、cast 和 CCD |
| 第 4 周 | 第 06、07 篇；堆叠、单摆和弹簧 | 子步/阻尼对照记录、一个关节结构图 | 解释累计冲量、热启动和约束自由度 |
| 第 5 周 | 第 09、10 篇；睡眠与多线程比较 | 数据布局图、不同 worker 数的结果记录 | 区分 island/set/color/block 与确定性 |
| 第 6 周 | 第 11、12 篇；快照恢复与小型基准 | 可复现录制、状态对比和实验报告 | 能定位一次差异发生在哪个阶段 |

如果主要目的是做游戏，优先完成第 01、02、03、07、08、12 篇；如果主要目的是研究算法，重点走第 03→04→05→06→09 篇，遇到基础问题返回第 10 篇。

## 每次实验用同一份记录模板

```text
问题：我想解释什么现象？
代码位置：公开 API → 内部函数 → 相关数据结构
基线：提交、构建模式、精度模式、worker 数、dt、子步数、初态
假设：改变一个参数后，预期结果为什么会变？
操作：只改变哪一个因素？
结果：数值、事件、截图或 profile；实际和预测的差异
解释：回到哪个条件、公式或数据迁移找到了原因？
复现：测试组名或样例名称，具体操作与参数
```

## 最后做一个综合练习

搭建“地面 + 五个堆叠盒子 + 一个铰接摆锤 + 一个传感器区域”的场景：

1. 使用固定时间步，记录位置、接触开始/结束和触发区进入/离开。
2. 改变子步数与摩擦，先预测再观察；保持其他初始条件相同。
3. 使用调试绘制定位接触点，说明一个盒子如何从 Shape 进入空间树、Contact 和求解器。
4. 分别以串行与多个 worker 重建相同场景，比较测试式的状态指标。
5. 录制运行，验证回放；保存一个快照并恢复，解释为什么业务对象关联需要单独处理。

完成后写一页说明：一个稳定接触依赖哪些模块；性能主要消耗在哪里；你还没有验证哪些边界。能回答这些问题，比“每个源文件都看过”更能说明你理解了项目。

## 常用术语速查

| 术语 | 在本文中的含义 |
| --- | --- |
| Broad phase / 宽相 | 用空间索引等手段筛选潜在碰撞对 |
| Narrow phase / 窄相 | 对候选形状进行精细碰撞计算 |
| AABB | 轴对齐包围盒 |
| Manifold / 接触流形 | 法线、接触点、分离信息等求解所需数据 |
| Speculative contact / 预测接触 | 在小间距下提前准备以限制穿透的接触约束 |
| Impulse / 冲量 | 动量变化，直接影响速度 |
| Warm start / 热启动 | 复用已有冲量作为新一轮求解的初值 |
| CCD / 连续碰撞检测 | 研究时间区间内的碰撞，缓解高速穿透 |
| TOI / 碰撞时间 | 运动区间中求得的相遇时刻或时间比例 |
| Island / 岛 | 通过约束联系起来的一组模拟对象 |
| SIMD | 一条指令对多个数据通道做同类运算 |
| Determinism / 确定性 | 在约定的初态、输入与执行条件下产生一致结果 |

完整外部读物、阅读目的和版本注意事项见[第 13 篇](learning/13_reading.md)。
